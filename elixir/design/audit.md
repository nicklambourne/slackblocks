# Elixir plan audit and revisions

**Date:** 11 October 2026. **Result:** 16 findings addressed in revision 2 of the [plan](plan.md) and [inventory](parity.json). These are planning fixes, not claims of an implemented or tested Elixir package.

## Findings and changes

| ID | Finding | Revision and verification gate |
| --- | --- | --- |
| A01 | The original baseline had fallen behind master. New guidance added specific README and monitoring requirements. | Refreshed to `250a5fe4e5cdacf51823ef0371c5d3a8dc4a3bc3`; archived current guidance. Require both collapsed README accordions, both badge rows, exact palette/style/order, default-branch CI badges and post-cache aggregate verification. Select official light/dark Elixir assets and its documented `8847B9` colour. |
| A02 | MIT-only packaging would omit the repository's BSD alternative. | Preserve MIT OR BSD-3-Clause in docs, both license texts in the archive and both SPDX identifiers in Hex metadata; verify artifact contents. |
| A03 | Decimal 2.x-only would conflict with current Ecto. Dependency floors were also vague. | Propose Decimal `~> 2.4 or ~> 3.0` and an explicit Jason 1.4.5 floor. Test minimum/latest of both Decimal majors and a current Ecto consumer. The range remains subject to actual compiler/resolver verification. |
| A04 | Constructor defaults, wire parse omission and required fields with defaults contradicted one another. | Define a presence matrix for new/change/from_map/decode, including required File/IconButton defaults. Parsing explicitly clears absent optional fields. Promise canonical wire round trips rather than impossible reconstruction of input history. Add per-field inventory policies. |
| A05 | The tagged-error promise did not account for custom Jason encoder exceptions or JSON syntax errors. | Specify success/failure shapes for each public boundary. Library encode validates first; direct Jason protocol calls may raise ValidationError. JSON syntax retains Jason.DecodeError. Test direct and nested calls. |
| A06 | Parsing/struct invariants were underspecified beyond ordinary constructors. | Static module/role selectors, receiving-context discriminator dispatch, tagless plan-task reconstruction, forged/missing/extra struct keys, constructor-only text conveniences and exact opaque JSON terms are now explicit. |
| A07 | Numeric policy remained too open, and duplicate keys could disappear before validation. | Propose a shortest-decimal equality policy and strict integer kinds; verify overflow/underflow/context independence on both Decimal majors. Decode ordered objects before duplicate checks, preserve integer-list metadata, and use an explicit structural comparator rather than loose equality. |
| A08 | Future API evolution was missing despite being required by the guide. | Document additive fields/roles/enum atoms, catch-all matches, default/signature stability and compatibility review for narrowing changes. Avoid a cross-version binary-struct persistence promise. |
| A09 | Running full checks under every matrix compiler conflicted with pinned generation formatting and duplicated work. | One canonical formatter/tooling lane; explicit runtime/resolution profiles elsewhere. Add cold parallel compilation, compile-cycle, escaping and case-insensitive path checks. Respect host volume placement. |
| A10 | A coverage percentage could exclude modules that tests never loaded. | Derive the handwritten denominator from compiled production modules; prove an unexercised module is still counted. Retain explicit rule cases and independent public export discovery. |
| A11 | Own-package lock guidance imported assumptions that do not apply to Mix path dependencies. Production archive isolation needed detail. | Guard declared requirements and loaded app versions; require lock records only when real Hex records exist. Add no-dev-dependency production builds, no Git/spec reads and an existing-Jason-consumer upgrade scenario. |
| A12 | SDK reasoning relied partly on mutable upstream source, and bounded retries could accidentally stack. | Inspected the published slack_elixir 1.2.2 archive. Keep the Req JSON send path, execute the displayed source, and disable middleware retries when the example implements its own rate-limit handling. |
| A13 | A full Hex publish dry run was incorrectly required to work without credentials. | PRs build package/docs and use the docs-only dry run. The complete publish dry run belongs in protected readiness because the inspected Hex CLI performs account discovery. No PR credentials or fake key workaround. |
| A14 | Advancing versions in an earlier docs PR could leave the old eight-publisher guard able to release an incomplete target. | PR 5 now freezes outgoing docs, advances versions and installs the nine-language disabled guard atomically. PR 6 completes site/README parity. Test old coherent and new disabled release states before enabling publication. |
| A15 | Generic required-check wording could lead to a path-filtered publisher job that never reports on unrelated PRs. | Require an always-created Elixir workflow, conservative relevance detection and explicit aggregate outcomes; retain existing protection and inspect real relevant/unrelated jobs. |
| A16 | The expanded inventory was not portable enough to commit as-is and lacked specific native/delivery acceptance rows. | Add 16 native cases, eight delivery requirements, five public boundaries, three supporting types and per-field presence/coercion policies. Require a compact portable committed form referencing the live registries, without duplicating them as a second source of truth. |

## Primary evidence

- Current repository guidance and README are captured in [the reference snapshot](parity.json). No shared model, limit, fixture or vocabulary bytes changed between the original and audited commits.
- Dual licensing is stated in [the current README snapshot](https://github.com/nicklambourne/slackblocks/blob/250a5fe4e5cdacf51823ef0371c5d3a8dc4a3bc3/README.md), with both license files present at the repository root.
- Ecto 3.14's published dependency requires Decimal 3.x; both reviewed Decimal majors declare a runtime floor below the proposed Elixir floor. This establishes a resolver concern, not a successful native compilation. [Ecto metadata](https://hex.pm/api/packages/ecto/releases/3.14.0), [Decimal 2.4.1 metadata](https://hex.pm/api/packages/decimal/releases/2.4.1), [Decimal 3.2.0 metadata](https://hex.pm/api/packages/decimal/releases/3.2.0)
- Jason's encoder catches specific internal failures and does not catch an arbitrary ValidationError raised by a protocol implementation. Its decoder exposes ordered-object and decimal options. [Pinned encoder source](https://github.com/michalmuskala/jason/blob/v1.4.5/lib/encode.ex), [pinned decoder options](https://github.com/michalmuskala/jason/blob/v1.4.5/lib/jason.ex)
- Hex 2.5.1 calls account discovery in the full publish path even when writes will be skipped; the docs-only dry-run branch avoids that owner prompt path. This is source inspection, not execution with a local Hex CLI. [Pinned publish task](https://github.com/hexpm/hex/blob/v2.5.1/lib/mix/tasks/hex.publish.ex)
- The actual [published Slack client source](https://repo.hex.pm/tarballs/slack_elixir-1.2.2.tar) confirms client/1 creates a Req request and post/3 uses form encoding. Read from the [Hex 1.2.2 archive](https://repo.hex.pm/tarballs/slack_elixir-1.2.2.tar), with no extraction into a checkout.
- The official brand page supplies light/dark SVGs and colour `#8847B9`. [Elixir brand policy](https://elixir-lang.org/trademarks/)

## Verification and limits

The scratch verification record checked source hashes, exact inventory sets, links, new policies and plan consistency. Both source checkouts were left unchanged during the audit; fetching only refreshed remote references. Current implementation evidence is recorded in [checkpoint.md](checkpoint.md).

No Elixir implementation, dependency installation, native prototype, CI run, account change or release was performed. Proposed dependency bounds, runtime pairs, numeric/resource policy and native API ergonomics still require their implementation checkpoints. The Hex identity setup URL again returned HTTP 404; bootstrap-token publication remains explicitly planned, with OIDC as a later verified transition. NuGet still lists 2.6.0; resolving that existing publication issue remains a prerequisite for activating the next coordinated release.
