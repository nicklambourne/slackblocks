# Threaded reply

Attach the parent message timestamp to the outgoing request. Preserve the original channel together with that timestamp when handling a delayed interaction.

<RecipeOutput recipe="threaded-reply" outputs={recipeOutputs} />

## Code

<LanguageContent>

<Python>

Pass `thread_ts` (the timestamp of the parent message) to reply in-thread.

```python
from slackblocks import Message, SectionBlock

reply = Message(
    channel="#general",
    thread_ts="1700000000.000100",
    blocks=SectionBlock("Reticulating splines... 30% complete."),
)
print(reply.json())
```

</Python>

<TypeScript>

```ts
import * as S from "@nicklambourne/slackblocks";

const message = S.Message().channel("C1").text("Deployment complete").build();
// thread_ts is a transport option outside this implementation's modeled fields.
console.log(JSON.stringify({...message, thread_ts: "1700000000.000100"}));
```

</TypeScript>

<Go>

```go
package main

import (
	"encoding/json"
	s "github.com/nicklambourne/slackblocks/go/v3"
	"os"
)

func main() {
	value, err := s.NewMessage().Channel("C1").Text("Deployment complete").Build()
	// thread_ts belongs to the transport request; it is not validated by this builder.
	if err == nil {
		value["thread_ts"] = "1700000000.000100"
	}
	if err != nil {
		panic(err)
	}
	if err := json.NewEncoder(os.Stdout).Encode(value); err != nil {
		panic(err)
	}
}
```

</Go>

<Rust>

Threading is an unmodeled delivery option. Add the parent message timestamp as
a checked extension, or set `thread_ts` on your HTTP/Slack request.

```rust
use slackblocks::*;
fn main() -> Result<(), Box<dyn std::error::Error>> {
    let reply = MessagePayload::builder("C01234567")
        .extension("thread_ts", "1700000000.000100")
        .text("30% complete")
        .block(
            SectionBlock::builder()
                .text("Reticulating splines... 30% complete.")
                .build()?,
        )
        .build()?;
    println!("{}", serde_json::to_string(&reply)?);
    Ok(())
}
```

</Rust>

<Elixir>

```elixir
wire = Slackblocks.Message.new!(channel: "C1", text: "Deployment complete")
|> Slackblocks.to_map!()
Map.put(wire, "thread_ts", "1700000000.000001")
```

Transport-specific fields outside the shared model can be added to the validated map in application code. Such additions are not validated by slackblocks.

</Elixir>

<Haskell>

```haskell
{-# LANGUAGE OverloadedStrings #-}

import Data.Aeson (encode)
import qualified Data.Aeson
import qualified Data.Map.Strict as Map
import Slackblocks

example =
  buildMessagePayload
    ( (messagePayload "C1")
        { messagePayloadText = Just "Deployment complete",
          messagePayloadExtensions = Map.fromList [("thread_ts", Data.Aeson.String "1700000000.000001")]
        }
    )
```

`thread_ts` is an explicit unmodeled extension. It cannot override reserved or modeled keys; application-specific extension semantics are not validated.
