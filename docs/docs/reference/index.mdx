reference gives the callable spelling and parameter types.

## References in a source checkout

Most current reference pages are generated during the documentation build and
intentionally ignored by Git. Their absence from a fresh checkout does not mean
the public type is undocumented. Install the documented development toolchains,
then run `pnpm --filter @slackblocks/docs generate` to create the references or
`pnpm --filter @slackblocks/docs build` to generate and verify the complete site.
The build reads the native public APIs; do not copy an older versioned reference
into the current tree or hand-edit generated signatures. See the
[maintenance guide](/contributing/block-kit-updates) for generation and release checks.

## Choose a payload and receiving surface

| Task | Native payload | Additional receiving requirements |
| --- | --- | --- |
| Post or update a message | Message / MessagePayload | Channel ID, fallback text, suitable token/scopes; inspect the API result. |
| Incoming webhook | WebhookMessage | Configured webhook URL and endpoint-specific response handling. |
| Interaction response | MessageResponse / WebhookMessage | Genuine `response_url` or immediate command response; visibility/replacement rules differ from webhooks. |
| Open/update a modal | Modal / ModalView | View request envelope plus fresh trigger ID or existing view ID/hash. |
| Publish App Home | HomeTabView | Request envelope with the target user ID. |
| Display a registered remote file | FileBlock representation | Register/share through remote-file APIs, then retrieve; FileBlock is not directly postable. |

The [sending guide](/usage/sending_messages) supplies native examples. Check [parsing capabilities](/usage/recipes/parse-json) before accepting incoming JSON and [validation boundaries](/usage/validation-boundary) before relying on local acceptance. Field roles, allowed parents and surface restrictions are separate: for example, a value accepted as an input element is not automatically a section accessory. Use the native parameter type and that block’s official reference.

For each language, start with installation/runtime compatibility, construct and serialize a value, inspect an error, then follow the relevant sending and safe-edit recipe. General decoder support, automatic IDs and string coercion differ deliberately; the recipe and reference name those differences.
