# Sending Messages

`slackblocks` produces the JSON payloads that Slack APIs accept; it does **not** make HTTP calls itself. Send those payloads with the established Slack client for your language or any HTTP client.

## Other delivery surfaces

`slackblocks` provides specialized message classes for each Slack delivery surface. They all unpack the same way as `Message`.

### Incoming webhooks

```python
from slack_sdk.webhook import WebhookClient
from slackblocks import WebhookMessage, SectionBlock

webhook = WebhookClient(url="https://hooks.slack.com/services/...")
message = WebhookMessage(blocks=SectionBlock("Build complete :white_check_mark:"))

webhook.send(**message)
```

`WebhookMessage` supports webhook-only options like `response_type`, `replace_original`, and `delete_original`.

### Slash command / interaction responses

When responding to a slash command or interactive payload, use `MessageResponse`:

```python
from slackblocks import MessageResponse, SectionBlock

response_body = MessageResponse(
    blocks=SectionBlock("Got it! Working on that now..."),
    ephemeral=True,        # only visible to the invoking user
).json()
```

### Modals & home tabs

For modals and home tab views, build a `Modal` (or `HomeTabView`) and pass it to `views_open` / `views_publish`:

```python
from slack_sdk import WebClient
from slackblocks import Modal, SectionBlock

client = WebClient(token=environ["SLACK_API_TOKEN"])
modal = Modal(
    title="Confirm action",
    blocks=[SectionBlock("Are you sure?")],
    submit="Yes",
    close="Cancel",
)

client.views_open(trigger_id=trigger_id, view=modal.to_dict())
```

See [Modals reference](../reference/python/modals) and [Views reference](../reference/python/views) for the full surface.

## With `slack-go/slack`

slackblocks block builders implement `slack.Block`, so they fit directly into the native options accepted by [`github.com/slack-go/slack`](https://github.com/slack-go/slack). Keep the channel, fallback text, threading, unfurling, and other delivery options in slack-go; use slackblocks for the Block Kit content.

```go
package example

import (
	"context"
	"os"

	slackblocks "github.com/nicklambourne/slackblocks/go/v2"
	slack "github.com/slack-go/slack"
)

func send(ctx context.Context) (string, error) {
	client := slack.New(os.Getenv("SLACK_API_TOKEN"))
	_, timestamp, err := client.PostMessageContext(
		ctx,
		"C0123456",
		slack.MsgOptionText("Hello from slackblocks!", false),
		slack.MsgOptionBlocks(
			slackblocks.NewSectionBlock().Text("Hello, world!"),
		),
	)
	return timestamp, err
}
```

slack-go marshals each builder while applying `MsgOptionBlocks`. That runs slackblocks validation before any HTTP request is made and preserves newer block types and fields even when the pinned slack-go release does not model them itself.

Higher-level components expand to the same native type:

```go
blocks, err := slackblocks.NewPaginator().
	Blocks(
		slackblocks.NewSectionBlock().Text("Result one"),
		slackblocks.NewSectionBlock().Text("Result two"),
	).
	ActionIDPrefix("results").
	PageSize(1).
	SlackBlocks()
if err != nil {
	return err
}

_, _, err = client.PostMessageContext(
	ctx,
	"C0123456",
	slack.MsgOptionBlocks(blocks...),
)
```

## With the official Slack Java SDK

Completed slackblocks block values implement the Slack SDK's `LayoutBlock` interface directly. Keep the channel, fallback text, threading, unfurling, and other delivery options on `ChatPostMessageRequest`; no adapter is involved.

```java
import com.slack.api.Slack;
import com.slack.api.methods.MethodsClient;
import com.slack.api.methods.request.chat.ChatPostMessageRequest;
import io.github.nicklambourne.slackblocks.block.SectionBlock;
import java.util.List;

MethodsClient client = Slack.getInstance().methods(System.getenv("SLACK_API_TOKEN"));
SectionBlock block = SectionBlock.builder().markdownText("Hello, world!").build();

var response = client.chatPostMessage(ChatPostMessageRequest.builder()
    .channel("C0123456")
    .text("Hello from slackblocks!")
    .blocks(List.of(block))
    .build());
```

Validation runs in `build()` before the request is created. Use a channel ID where possible and always supply a short `text` fallback for notifications and accessibility.

Import slackblocks classes by name, because the SDK defines classes with the same simple names in `com.slack.api.model.block`.

Higher-level components produce the same native block values. `List.copyOf` widens their `List<Block>` result to the `List<LayoutBlock>` the SDK expects:

```java
import io.github.nicklambourne.slackblocks.block.Block;
import io.github.nicklambourne.slackblocks.component.Paginator;
import java.util.List;

List<Block> pages = Paginator.builder("search-results")
    .blocks(
        SectionBlock.builder().markdownText("Result one").build(),
        SectionBlock.builder().markdownText("Result two").build())
    .pageSize(1)
    .build();

client.chatPostMessage(ChatPostMessageRequest.builder()
    .channel("C0123456")
    .text("Search results")
    .blocks(List.copyOf(pages)) // widens List<Block> to List<LayoutBlock>
    .build());
```

## With the Slack Web API

slackblocks builds and validates the payload; `HttpClient` sends it. Put the channel, fallback text, blocks, and other delivery options on a `MessagePayload`, then post its JSON to `chat.postMessage` with a bot token:

```csharp
using System.Net.Http.Headers;
using System.Text;
using System.Text.Json.Nodes;
using Slackblocks.Blocks;
using Slackblocks.Payloads;

var message = new MessagePayload(
    "C0123456",
    text: "Hello from slackblocks!",
    blocks: [new SectionBlock(text: "Hello, world!")]);

using var http = new HttpClient();
using var request = new HttpRequestMessage(HttpMethod.Post, "https://slack.com/api/chat.postMessage")
{
    Content = new StringContent(message.ToJson(), Encoding.UTF8, "application/json"),
};
request.Headers.Authorization = new AuthenticationHeaderValue("Bearer", Environment.GetEnvironmentVariable("SLACK_BOT_TOKEN"));
using var response = await http.SendAsync(request);
var result = JsonNode.Parse(await response.Content.ReadAsStringAsync())!;
if (result["ok"]?.GetValue<bool>() != true)
{
    throw new InvalidOperationException($"Slack rejected the message: {result["error"]}");
}
```

Validation runs in each constructor, before the request exists. Use a channel ID where possible and always supply a short `text` fallback for notifications and accessibility.

Higher-level components return ordinary blocks, so their results spread straight into the `blocks` collection:

```csharp
using Slackblocks.Blocks;
using Slackblocks.Components;
using Slackblocks.Payloads;

var results = Paginator.Create(
    "search-results",
    [new SectionBlock(text: "Result one"), new SectionBlock(text: "Result two")],
    pageSize: 1);

var message = new MessagePayload("C0123456", text: "Search results", blocks: [.. results]);
```

## Serialize a complete payload

The Rust crate builds validated payloads and makes no network requests. Serialize
with Serde, then send the JSON through your application's HTTP or Slack client.
This executable example writes the body that can be submitted to `chat.postMessage`:

```rust
use slackblocks::*;

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let message = MessagePayload::builder("C01234567")
        .text("Deployment complete")
        .block(
            SectionBlock::builder()
                .text("Deployment complete")
                .build()?,
        )
        .build()?;
    println!("{}", serde_json::to_string(&message)?);
    Ok(())
}
```

Save the output as `message.json`. For a manual request, set `SLACK_BOT_TOKEN`
in your environment and use:

```sh
curl --fail-with-body https://slack.com/api/chat.postMessage \
  -H "Authorization: Bearer $SLACK_BOT_TOKEN" \
  -H 'Content-Type: application/json; charset=utf-8' \
  --data-binary @message.json
```

Check both the HTTP status and Slack's JSON `ok`/`error` response. Do not print or
commit the token. A successful local build validates the documented Block Kit
contract; permissions, channel membership and delivery remain Slack concerns.

## With Slack Morphism

[Slack Morphism](https://github.com/abdolence/slack-morphism-rust) is a community
Rust Slack client supporting the Web API, Events API and Socket Mode. Slack's
[official SDK catalogue](https://docs.slack.dev/tools/) currently has no Rust SDK.

The example below passes our `MessagePayload` directly to the SDK's generic
`http_post` method, which accepts `serde::Serialize`. Its higher-level
`chat_post_message` method requires its own request and block types. Sending our
payload directly preserves unknown extension fields and features the SDK may
not yet model. The response type reads only the channel and timestamp; blocks
returned by Slack do not need to pass through the SDK's block models either.

Rate control is enabled explicitly, with the SDK's `chat.postMessage` method
configuration, a workspace ID, and at most two retries after rate-limit
rejections. The application imposes a 60-second deadline including retry waits.
Reuse the client across calls so its rate-control state is shared. Slack's
[per-channel posting limit](https://docs.slack.dev/reference/methods/chat.postMessage/#rate-limiting)
still applies; coordinate senders in your application when necessary.

```rust title="rust/integrations/examples/slack_morphism.rs"
//! Keep Slack Morphism's authenticated transport and send slackblocks values directly.
use serde::Deserialize;
use slack_morphism::prelude::*;
use slackblocks::{MessagePayload, SectionBlock};
use std::time::Duration;

// Deserialize only the receipt, so new blocks echoed by Slack do not need SDK models.
#[derive(Debug, Deserialize)]
pub struct PostedMessage {
    pub channel: String,
    pub ts: String,
}

pub fn https_connector() -> std::io::Result<SlackClientHyperHttpsConnector> {
    // When both clients share an application, reqwest and Slack Morphism enable
    // different rustls providers. Choose ring unless the application chose one.
    let _ = rustls::crypto::ring::default_provider().install_default();
    SlackClientHyperConnector::new()
}

pub fn rate_control() -> SlackApiRateControlConfig {
    SlackApiRateControlConfig::new().with_max_retries(2)
}

pub async fn send_message<C>(
    session: &SlackClientSession<'_, C>,
    message: &MessagePayload,
) -> ClientResult<PostedMessage>
where
    C: SlackClientHttpConnector + Send,
{
    // The typed chat_post_message method requires Slack Morphism's own block types.
    // Its generic transport accepts Serialize and preserves all our payload fields.
    session
        .http_session_api
        .http_post(
            "chat.postMessage",
            message,
            Some(&CHAT_POST_MESSAGE_SPECIAL_LIMIT_RATE_CTL),
        )
        .await
}

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error + Send + Sync>> {
    let token = SlackApiToken::new(std::env::var("SLACK_BOT_TOKEN")?.into())
        .with_team_id(std::env::var("SLACK_TEAM_ID")?.into());
    let channel = std::env::var("SLACK_CHANNEL_ID")?;
    let message = MessagePayload::builder(channel)
        .text("Deployment complete")
        .block(
            SectionBlock::builder()
                .text("Deployment complete")
                .build()?,
        )
        .build()?;
    let client = SlackClient::new(https_connector()?.with_rate_control(rate_control()));
    let session = client.open_session(&token);
    // Bound the whole operation, including the SDK's rate-limit retries.
    let posted =
        tokio::time::timeout(Duration::from_secs(60), send_message(&session, &message)).await??;
    println!("Posted {} to {}", posted.ts, posted.channel);
    Ok(())
}
```

## With reqwest

An application that only needs to send messages can use
[reqwest](https://docs.rs/reqwest/latest/reqwest/) directly. Its `.json(&message)`
method uses our Serde implementation; no adapter or intermediate JSON string is
required. This example checks HTTP status and Slack's `ok`/`error` envelope,
respects a numeric `Retry-After` on 429, and makes at most two retry attempts.
Missing or invalid `Retry-After` returns a rate-limit error for the application to
handle. Network errors and server failures are returned without automatic retry,
because a message may already have been accepted. The overall operation has a
60-second deadline and redirects are disabled.

```rust title="rust/integrations/examples/reqwest.rs"
//! Send a validated payload with an application-owned HTTP client.
use reqwest::{Client, StatusCode};
use serde::Deserialize;
use slackblocks::{MessagePayload, SectionBlock};
use std::time::Duration;

const MAX_RATE_LIMIT_RETRIES: usize = 2;

#[derive(Debug, Deserialize)]
pub struct PostedMessage {
    pub channel: String,
    pub ts: String,
}

#[derive(Debug, thiserror::Error)]
pub enum SendError {
    #[error(transparent)]
    Http(#[from] reqwest::Error),
    #[error("Slack rate limit exceeded (Retry-After: {retry_after:?})")]
    RateLimited { retry_after: Option<Duration> },
    #[error("Slack rejected the message: {0}")]
    Api(String),
    #[error("Slack returned an invalid response")]
    InvalidResponse,
}

/// Retry only explicit 429 rejections, never an ambiguous timeout or server error.
/// `api_url` is Slack's API base URL in production; tests use a local mock server.
pub async fn send_message(
    client: &Client,
    api_url: &str,
    token: &str,
    message: &MessagePayload,
) -> Result<PostedMessage, SendError> {
    let mut retries = 0;
    loop {
        let response = client
            .post(format!("{api_url}/chat.postMessage"))
            .bearer_auth(token)
            .json(message)
            .send()
            .await?;
        if response.status() == StatusCode::TOO_MANY_REQUESTS {
            let retry_after = response
                .headers()
                .get(reqwest::header::RETRY_AFTER)
                .and_then(|value| value.to_str().ok()?.parse::<u64>().ok())
                .map(Duration::from_secs);
            if retries < MAX_RATE_LIMIT_RETRIES {
                if let Some(delay) = retry_after {
                    // Release the response before sleeping; do not retry without a delay.
                    drop(response);
                    retries += 1;
                    tokio::time::sleep(delay).await;
                    continue;
                }
            }
            return Err(SendError::RateLimited { retry_after });
        }
        let body: serde_json::Value = response.error_for_status()?.json().await?;
        match body.get("ok").and_then(serde_json::Value::as_bool) {
            Some(true) => {
                return serde_json::from_value(body).map_err(|_| SendError::InvalidResponse);
            }
            Some(false) => {
                let error = body
                    .get("error")
                    .and_then(serde_json::Value::as_str)
                    .ok_or(SendError::InvalidResponse)?;
                return Err(SendError::Api(error.to_owned()));
            }
            None => return Err(SendError::InvalidResponse),
        }
    }
}

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    let token = std::env::var("SLACK_BOT_TOKEN")?;
    let channel = std::env::var("SLACK_CHANNEL_ID")?;
    let message = MessagePayload::builder(channel)
        .text("Deployment complete")
        .block(
            SectionBlock::builder()
                .text("Deployment complete")
                .build()?,
        )
        .build()?;
    let client = Client::builder()
        .timeout(Duration::from_secs(30))
        .redirect(reqwest::redirect::Policy::none())
        .build()?;
    // Bound the whole operation, including Retry-After waits.
    let posted = tokio::time::timeout(
        Duration::from_secs(60),
        send_message(&client, "https://slack.com/api", &token, &message),
    )
    .await??;
    println!("Posted {} to {}", posted.ts, posted.channel);
    Ok(())
}
```

## Choosing a PHP transport

Slack does not list an official PHP SDK. [JoliCode](https://github.com/jolicode/slack-php-api)
is a community SDK; [Laravel's Slack notification channel](https://github.com/laravel/slack-notification-channel)
is the framework-native option. The core Slackblocks package requires neither.
Native cURL works without an SDK.

The complete, tested adapters live in the repository's
[`php/integrations`](https://github.com/nicklambourne/slackblocks/tree/master/php/integrations)
example project. Run `composer install` there and adapt the example files into your
application. `Slackblocks\Examples` is not part of the published core package.

### JoliCode and native cURL

The following standalone example constructs a payload and returns a callable.
Invoke it deliberately with an application token to send; merely loading it
performs no network request.

```php title="php/integrations/examples/jolicode.php"
<?php

declare(strict_types=1);

require 'vendor/autoload.php';

use Slackblocks\{MessagePayload, SectionBlock};
use Slackblocks\Examples\Sending;

$message = new MessagePayload(channel: 'C0123456789', text: 'Hello', blocks: [new SectionBlock('*Hello* from PHP')]);
return static fn(string $token, ?\Psr\Http\Client\ClientInterface $http = null): array => Sending::jolicode($message, $token, $http);
```

```php title="php/integrations/examples/curl.php"
<?php

declare(strict_types=1);

require 'vendor/autoload.php';

use Slackblocks\{MessagePayload, SectionBlock};
use Slackblocks\Examples\Sending;

$message = new MessagePayload(channel: 'C0123456789', text: 'Hello', blocks: [new SectionBlock('*Hello* from PHP')]);
return static fn(string $token, string $endpoint = 'https://slack.com/api/chat.postMessage'): array => Sending::curl($message, $token, $endpoint);
```

JoliCode receives `blocks`, `attachments`, and `metadata` as JSON form parameters,
so new nested types bypass its generated Block Kit models. Unknown **top-level**
Web API parameters may still be rejected by the SDK; cURL sends the complete
`toJson()` body. Native cURL requires `ext-curl` only in the sending application.

Both adapters reject non-success HTTP responses, Slack `ok: false`, malformed
JSON, redirects and timeouts. Only explicit HTTP 429 responses are retried, with
at most two retries and `Retry-After` of zero or one second. Longer/missing delays
fail for the application to reschedule. Five-second request limits bound the
default budget to 17 seconds. Ambiguous network failures and HTTP 5xx responses
are never automatically retried. A caller-injected PSR-18 client must supply
its own timeouts and redirect policy. The implementation and these boundaries
are exercised against a local HTTP server with fake tokens.

### Laravel notifications

Return the adapter's result from your notification's `toSlack()` method. It uses
Laravel's public `usingBlockKitTemplate()` API and preserves Laravel routing and
options. The example project tests the real Slack notification channel with its
HTTP fake.

```php title="php/integrations/examples/laravel.php"
<?php

declare(strict_types=1);

require 'vendor/autoload.php';

use Slackblocks\SectionBlock;
use Slackblocks\Examples\LaravelTemplate;

$message = LaravelTemplate::message('C0123456789', 'Hello', [new SectionBlock('*Hello* from Laravel')]);
$message->unfurlLinks(false);
return $message;
```

This is a **blocks-only** bridge: set channel, fallback text and notification
options separately. An explicit channel from Laravel's notification route takes
precedence over the message's channel. It does not import full payloads or attachments. Laravel's
associative template decoder changes empty objects into arrays; the adapter
rejects those lossy inputs. Use the SDK or cURL path when such opaque objects
must survive. Laravel owns sending and retries for its notification channel.

### Webhooks, modals and responses

Use `WebhookMessage` for an incoming webhook, `ModalView` for the `view` parameter
of `views.open`/`views.update`, `HomeTabView` for `views.publish`, and
`MessageResponse` for slash-command or interaction responses. Serialize each
with `toJson()`; transport credentials, trigger IDs and application routing stay
in the sending application. Do not put a bot token into a preview URL or payload.
