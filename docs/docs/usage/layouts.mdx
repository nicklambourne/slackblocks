From **3.2.0**, a layout block groups native blocks into one to five rows, each containing one to three items. Each item wraps one block and controls its share of the row's width.

## Anatomy of a layout

![A layout contains a label and a row. The row contains two items: a wide item wrapping the API section and a narrow item wrapping the Healthy section. A separate fallback section reads API: Healthy.](/img/usage/layout-anatomy.svg)

Build from the inside out: create the child blocks, wrap each in an item, collect the items into a row, then put the row in the layout. The diagram shows the object structure; its nested outlines are annotations, not Slack grid lines.

## Basic example

This example places **API** beside **Healthy** in one row. The `wide` and `narrow` items request a 3:1 share of the available width. It shows the label, draws an outer border, and supplies a plain linear fallback. The code constructs a block without sending a message; add it to your message's blocks and include **API: Healthy** in the message's top-level text.

from slackblocks import LayoutBlock, LayoutRow, LayoutItem, PlainText, SectionBlock

layout = LayoutBlock(
    label="Service status", block_id="service-layout", is_label_visible=True,
    grid_lines="outer",
    rows=[LayoutRow(items=[
        LayoutItem(block=SectionBlock(text=PlainText("API"), block_id="service"), width="wide"),
        LayoutItem(block=SectionBlock(text=PlainText("Healthy"), block_id="status"), width="narrow"),
    ])],
    fallback=[SectionBlock(text=PlainText("API: Healthy"), block_id="fallback")],
)
print(layout)

        Rows(s.NewLayoutRow().Items(
            s.NewLayoutItem().Block(s.NewSectionBlock().TextObject(s.NewPlainText().Text("API")).BlockID("service")).Width(s.LayoutWidthWide),

        )).
        Fallback(s.NewSectionBlock().TextObject(s.NewPlainText().Text("API: Healthy")).BlockID("fallback")).Build()
    if err != nil { panic(err) }
    if err := json.NewEncoder(os.Stdout).Encode(layout); err != nil { panic(err) }

import io.github.nicklambourne.slackblocks.object.*;

        .gridLines(LayoutGridLines.OUTER).rows(row).fallback(fallback).build();
    System.out.println(layout.toJson());
  }
}

{-# LANGUAGE OverloadedStrings #-}

import Data.Aeson (encode)
import Data.Text (Text)
import Slackblocks

section :: Text -> Text -> Result SectionBlock
section text identifier = do
  content <- buildPlainText (plainText text)
  buildSectionBlock sectionBlock
    {sectionBlockText = Just (plainTextAsText content), sectionBlockBlockId = Just identifier}

example :: Result LayoutBlock
example = do
  service <- section "API" "service"
  status <- section "Healthy" "status"
  fallback <- section "API: Healthy" "fallback"
  left <- buildLayoutItem (layoutItem (sectionBlockAsLayoutChild service))
    {layoutItemWidth = Just LayoutWidthWide}
  right <- buildLayoutItem (layoutItem (sectionBlockAsLayoutChild status))
    {layoutItemWidth = Just LayoutWidthNarrow}
  row <- buildLayoutRow (layoutRow [left, right])
  buildLayoutBlock (layoutBlock "Service status" [row])
    {layoutBlockBlockId = Just "service-layout", layoutBlockIsLabelVisible = Just True,
     layoutBlockGridLines = Just LayoutGridLinesOuter,
     layoutBlockFallback = Just [sectionBlockAsLayoutFallback fallback]}

## Labels, widths and alignment

The required label is 1–150 Unicode code points. It is hidden unless `is_label_visible` is true; visible labels are bold text rather than headings, and hidden labels are not accessible names.

Widths are `narrow` (1), `standard` (2, the default) and `wide` (3). Explicit alignment is `start`, `center` or `end`; omission fills the cell. `grid_lines` accepts `none`, `rows` (outer plus horizontal dividers) or `outer`.

## Supported children and surfaces

| Placement | Supported content |
| --- | --- |
| Layout item | Actions, alert, card, carousel, container, context, data table, data visualization, divider, file, header, image, input, rich text, section, table, video |
| Fallback | Context, divider, header, image, rich text, section, table, video |
| Receiving surfaces | Messages, modals and App Home, subject to each child's own surface restrictions |

Direct nested layouts and markdown blocks are not layout children. A layout/container path allows at most two composite levels. A container may contain a layout where that container is supported; existing container-only nesting behavior is unchanged.

A row may contain only one carousel, data table or chart; a chart must receive **more than half** the row's total weight. A `wide` chart beside a `standard` item is valid; equal weights are not. In a three-item row, a `wide` chart beside two `narrow` items also has a strict majority (3 of 5); three omitted widths do not (2 of 6). The rule is independent of the chart's position.

## Fallback and validation

Fallback replaces the grid on clients without layout support. Explicit empty fallback remains empty. Child and fallback blocks must be valid on the receiving surface; for example, nesting an input in a modal still requires a submit label. Existing aggregate chart and text limits continue to apply. [Layout accounting](/usage/validation-boundary#layout-accounting) explains the retained top-level block limits and the observed Slack discrepancy.

[Official Slack layout reference](https://docs.slack.dev/reference/block-kit/blocks/layout-block).
